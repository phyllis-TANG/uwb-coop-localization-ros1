# 单车参考点、外参与 IMU 来源：最小补齐清单

适用阶段：完成 2026-10-21 九组权重敏感性诊断之后。当前只收集证据，不连接设备控制、不启动底盘、不重启节点、不改参数、不发串口命令、不发运动指令。用户可先仅执行第一步，将输出带回后再决定下一步。

## 2026-10-21 补充确认与到场顺序

用户已确认 UWB 在车上的安装位置始终未改变。相对近似几何中心的 [0.12,-0.08] m 安装测量可以按这一历史沿用；仍需核实几何中心与 Odom 消息所描述的车体参考点是否重合。不要再将历史天线是否移动列为未知，也不要将 Odom 世界坐标启动原点与车体参考点混为一谈。

预计周六 2026-10-24 到场，按 [现场优先清单](../20261024_SINGLE_CAR_CHECKLIST.md) 先取得实际启动文件，再查 Odom/IMU 与坐标模型。五包结果及在线化范围见 [阶段汇总](../SINGLE_CAR_FIVE_BAG_REVIEW_20261021.md)。

## 为什么先补这些，而不是继续调权重

目前天线偏移量相对“近似车体几何中心”测量；该点是否等于 Odom 的 `base_footprint` 原点尚未确认。Odom frame 的名字 `car2/odom_combined` 由启动参数指定，名字本身不能证明上游融合了 IMU。两个选定 bag 都没有 TF 话题，不能从其中恢复缺失的刚体变换。

这些是待核实的模型前提，不是已经确认的故障原因。不能用终点偏差最小化反推并宣布外参正确。本轮不选择新默认权重，也不预先决定添加 IMU 因子。

## 第一步：只读取得实际启动文件

在 Car2 已有的 SSH 终端内执行下列命令。无需启动 ROS、底盘、UWB 或运动节点。路径来自仓库的现场启动记录，不保证当前机器仍相同。

```bash
sed -n '1,240p' /home/wheeltec/wheeltec_robot/src/turn_on_wheeltec_robot/launch/include/base_serial.launch
```

把输出和任何报错带回即可。如果超过 240 行，再继续读取余下内容；不要把节选误称为完整文件。如果文件不存在，停止并保留报错，不创建该文件、不重装驱动。之后依据实际输出定位文件，不能猜节点名或驱动实现。

公开上传前人工检查：删除密码、令牌、Wi-Fi 密钥等秘密；与坐标/算法无关的设备序列号或内部地址可遮盖。我们需要的是坐标与计算定义，不需要凭据。

## 第二步：按启动文件追踪最小实现链

第一步返回后，再有针对性地只读收集以下材料，而不是上传整个车端工作空间。

| 材料 | 要回答的问题 | 不能据此直接断言 |
|---|---|---|
| 实际 base_serial.launch 及其相关 include/参数文件 | 启动了哪个包、可执行文件、车型、frame 参数；是否启动滤波节点 | launch 名字或注释就等于运行过程和历史版本 |
| 该节点发布 Odom、积分 XY/yaw 的源代码与相关定义 | XY/yaw 如何得到；是否使用编码器、陀螺仪或姿态；积分参考点是什么 | 话题名含 combined 就是 EKF，或者 Odom 与独立 IMU 无相关性 |
| 同一实现发布 IMU 的代码 | IMU 字段含义、轴、单位、姿态算法与源传感器；是否同源输入 Odom | IMU frame 名字已经说明了外参 |
| 与 base_footprint/base_link/gyro_link 有关的 URDF/Xacro/静态变换 | 平移、轴向和旋转的具体定义 | 无法辨认的车体中心可按零偏移处理 |
| 若只读环境允许，相关节点信息和相关参数快照 | 目前运行的节点、参数是否与文件一致 | 当前运行状态必然等于 10.18 录制时状态 |

若只有可执行文件、没有源代码，保留实际包/二进制版本和可用配置，向设备提供方索取对应版本的坐标与算法定义。公开的其它车型/版本代码只能作对照，不能替代本车证据。

记录文件路径、取得日期、可用的版本号/提交号及是否有修改。尽量找 10.18 当时的启动日志或文件备份。当前文件若已更新，不能单独证明历史 bag 使用了相同实现；将无法恢复的历史项明确标注为未知。

## 第三步：核实物理参考点，必要时补一份几何记录

先通过代码/厂家定义确定 Odom 参考点，再定位该点在车体上的物理位置。不要先假设它是几何中心、轮轴中心或任何特定点。

从这个已定义的参考点到天线中心记录车体系水平偏移，仍按 x 向前、y 向左；另外记录天线中心离地高度。对 IMU 记录其相对车体的安装轴方向和可确认的刚体变换。记录测量方法、不确定度、照片/草图、日期，以及安装有无移动。

10.18 的 Car2 记录为几何中心到天线 [0.12,-0.08] m、高度 0.20 m；它不是“已经失效”，只是与 Odom 原点的对应待核实。如果两原点重合得到证实，则保留原值；如果不重合，先通过独立几何关系换算，再做一个明确的模型改动对照，不能按终点表现选择位移。

今天的新测量只有在历史安装未改变有证据时，才可用于重解释 10.18 数据。若无法证实，历史结果保留原假设，新测量用于后续新采集。不要追溯套用到 10.11 等不同安装批次。

## 第四步：据证据决定模型改动

如果坐标定义和物理量测一致，外参核查可能只会确认旧模型，无须强行“修复”。如果发现不一致，先冻结独立量测的变换，再进行单一模型改动对照，保留原结果和全部失败案例。

若 Odom 已使用同一陀螺仪，直接再加一份 IMU 约束可能重复使用相关信息；应先确定测量模型和相关性处理，再比较合理的因子组合。若 Odom 没有使用 IMU，也仍需验证坐标、时间戳、偏置和噪声，不能仅凭有 IMU 话题就直接融合。

## 第五步：必要的新数据，不必现在立刻重采

先完成前四步，再另行确认现场安全与运动授权。当前清单不包含实车执行命令。

| 目标 | 最小有用证据 |
|---|---|
| 区分转弯几何、外参与朝向/遮挡相关测距变化 | 独立量测转向前后的天线中心和车体方向；或在可独立核对的位置重复多个朝向，每次重新量天线中心 |
| 验证冻结算法的泛化 | 未用于模型/参数选择的新重复轨迹；记录天线起点、中间停留点、终点、朝向及量测不确定度 |
| 验证连续轨迹精度 | 连续独立位置参考；只测三个停留点不能称全轨迹 RMSE |

车体在原地转向时，偏置安装的天线会沿杆臂旋转，不能当作固定天线位置。同样，一个方向的一次停留不足以确认可泛化的朝向偏置模型。标定数据、开发诊断数据和最终验证数据分开，并且分清不同安装批次。

若后续补录 TF，应记录 /tf 和 /tf_static 的发布来源、时间和实际是否完整，同时保存实际启动文件和版本。没有观测到某个变换不等于它的值为零；今天的 TF 也不能自动补成历史 TF。
