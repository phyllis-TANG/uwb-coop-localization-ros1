# 单车 Python 顺序回放基准（2026-10-22）

现有固定高度 SE(2) Odom＋UWB 模型按 bag 接收记录逐条更新。IMU 仅统计消息和时间头，没有独立 IMU 因子；Odom 是否已使用陀螺仪仍需现场核实。

## 输入和模型

- 首轮使用 10.18 的 005135 正常完成包和 004023 N10 异常包，运行前校验 SHA-256。
- 直接复用未改动的历史求解器 `docs/field_tests/single_car_historical_L_20261021/results/evidence/new_graph.py`，校验其冻结哈希。
- 基站、P1 修正、因子权重、1 秒状态间隔、±0.4 秒测距中位数窗和每链路至少 5 个样本均沿用已有基线；没有新增异常测距筛选。
- 起点天线 [2,2,0.20] 米和车头 +Y 为已确认外部输入，见[用户确认](../../../datasets/field_raw/provenance/user_confirmations_20261020.md)。天线安装始终未变；[0.12,-0.08] 米所对应的近似几何中心与 Odom 车体参考点相同仍是假设。
- 人工终点和评价窗只在回放完成后评价使用，不传入估计器。

冻结输入见 [protocol.json](protocol.json)。既有离线结果见 [P1 迁移结果](../20261018/single_car_transfer_20261021/results/fusion_trial/summary.json)。

## 回放策略

1. 接收记录决定数据何时可用；消息头用于测量关联。保留两套时间，不按整包消息头重新排序，不用整包统计拟合时钟。
2. 状态 t 的统计窗在接收时钟 t+1 秒关闭；等于截止时刻的消息也计入。1 秒是开发设置，不是实测网络延迟或当前时刻定位频率。
3. Odom 插值的两端都必须已经收到，缺少包围区间时明确报告，不悄悄外推。
4. 关闭的统计窗只生成一次因子，迟到数据单列计数。初始化已经错过的截止时刻跳过并记录。
5. 前两个有效状态为 Odom 预测，至少三个状态后尝试图求解。失败/未收敛状态单列，用上一发布位置加 Odom 增量预测，不接受失败迭代为融合输出。
6. EOF 只推进到最后一条记录的接收时间，不虚构后续数据或时钟。
7. 保留全部已到达历史，每次从继承的 Odom 初值求解完整前缀；本版没有固定窗口、边缘化或增量后端。

数据中消息头与记录时钟有偏移，两者差值不直接表示网络延迟。本程序是未限速事件回放；模拟截止时间、求解墙钟耗时和估算排队时间分别记录，不能替代 ROS/车载实时测速。

## 运行

在独立 Python 3.12 环境、仓库根目录：

```bash
python -m pip install -r tools/requirements-october-modern.txt
python -m unittest discover -s tools -p 'test_single_car_sequential_replay.py' -v
python tools/run_single_car_sequential_baseline.py --output run-results
```

输出目录必须不存在。程序不启动 ROS、串口或运动发布器，不操作小车。

## 结果与验证

运行结果见 [results/REPORT.md](results/REPORT.md)。`published.csv` 保留当时逐次发布的位置；`final_smoothed.csv` 是整包结束后对历史状态的修正，分别评价。`updates.json` 记录预测、失败、支持样本和优化状态；`frozen_keyframe_inputs.json` 保存实际送入图的输入。

测试覆盖修改/截断未来消息后过去输出不变、发布记录不被后续平滑改写、截止边界与迟到观测、缺少插值端点、时间顺序异常、初始化和 EOF、失败回退，以及历史求解器同输入一致性。两个真实包还分别截断到 30 秒重跑，核对已发布输出；完成后独立生成离线输入，复核最终前缀和原归档终点差。

这两个包已用于开发，缺少连续轨迹真值；终点差和相对离线轨迹的变化不能代表全程定位精度。下一步在这个基准上实现固定窗口和正确的边缘化，再接入 ROS 回放。IMU 因子和双车协同另行处理。
