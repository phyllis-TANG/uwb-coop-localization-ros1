# 夜间自主作业：离线诊断、回归与后续开发

先读 [本轮入口](README.md)、[沙盒端任务书](RUNBOOK_SANDBOX.md)、
[实验清单](EXPERIMENTS.md)、[验收报告](QC_REPORT.md)。本任务针对已录数据，
不是继续驱动小车的现场任务。

## 1. 已有命令能做什么

`tools/field_20261024_25/run_nightly.py` 是已经实现的有限作业执行器：

1. 检查 manifest、geometry、视觉/UWB身份及整包开发/留出划分。
2. 运行本轮准备、解析、媒体检查、夜间执行器自身的单元测试。
3. 分别运行仓库已有的11组离线回归：单车场景、因果回放、固定窗、双车图、
   双车对照、静止置信、测距置信、单车完好性、worker I/O、评价以及独立双车适配。
4. 在八个输入bag已到齐且SHA256吻合时，重新执行完整bag QC。

这些回归包括合成故障和信息隔离检查；其历史合成模型/阈值只是回归夹具，
**不直接作为2026-10-25新数据的模型、外参或有效阈值**。它不会自动重跑全部历史实验，
不会下载视频，不会启动ROS，不会伪装成已实现的全套新定位解算器。

默认14个作业，每个都有超时。整个计划最多6小时，最多64个作业，
每项在本次运行及后续恢复中最多实际尝试两次。第一次失败先记录并继续独立任务；
只有再次执行匹配的 `--resume` 才会重试，**没有无限重试，也不为了耗满6小时重复运行**。
计划提前完成就结束。剩余自主开发见第5节。

## 2. 启动：只需交给沙盒端一次

在合并本PR后按入口任务书取得干净的新checkout并创建自己的分析分支。
先记录HEAD、工作树和配置哈希，不要在其他工作端正在编辑的目录里启动。
以下命令在仓库根目录执行，推荐Linux/WSL上的Python3.10或更高版本。
不会修改Melodic的Python2或系统ROS环境。

```bash
python3 -c 'import sys; assert sys.version_info >= (3, 10), "nightly dependency set requires Python 3.10+"'
python3 -m venv "$HOME/.venvs/uwb-field-nightly"
PYTHON="$HOME/.venvs/uwb-field-nightly/bin/python"
"$PYTHON" -m pip install -r tools/field_20261024_25/requirements.txt
"$PYTHON" -m pip install -r tools/requirements-integrity-feasibility.txt

DATA_ROOT="$HOME/uwb-field-data/20261024_25"
OUTPUT_ROOT="$HOME/uwb-field-results/sandbox/nightly_$(date +%Y%m%d_%H%M%S)"
"$PYTHON" tools/field_20261024_25/prepare.py \
  --data-root "$DATA_ROOT" --assets bags --extract

"$PYTHON" tools/field_20261024_25/run_nightly.py --plan-only
"$PYTHON" tools/field_20261024_25/run_nightly.py \
  --data-root "$DATA_ROOT" --output "$OUTPUT_ROOT" --max-hours 6
```

若只为今晚的bag诊断，下载38MB左右的 `bags` 归档就够了，不需要重复下载3GB以上视频。
如依赖安装失败，保留错误并定位版本问题，在隔离环境解决；不能把失败的命令当通过。
执行器不负责安装依赖或联网下载，缺包会在该任务日志中明确失败，缺bag只会让bag作业BLOCKED，
不阻塞与其独立的回归测试。

这是前台程序。**仓库文档不能让一个已经停止的Codex任务自行继续，也不能保证关闭会话后仍运行**。
应在能够持续运行的沙盒任务中执行；若本地终端执行，可以在已有tmux会话中运行并确认进程实际存在。
不需要为了这次任务安装新的后台服务。不能把“命令已写好”报告为“夜间作业已启动”。

## 3. 中断、恢复和明早读取

结果均写到Git仓库外。`run.json` 保存冻结指纹、原始截止时刻、逐项状态与历史尝试；
`tasks.jsonl` 追加开始、完成、阻塞、恢复事件；`summary.md` 在每项后更新。
每项输出保存在 `jobs/<job_id>/attempt_0001/` 的stdout/stderr；bag作业的
`artifacts/bag_qc.json` 和 `BAG_QC_REPORT.md` 保存完整结构与采集链路验收。

恢复时用**同一个真实路径**，不要重新运行日期表达式创建另一目录：

```bash
# 将这里替换为上一条命令实际打印/创建的目录。
OUTPUT_ROOT="$HOME/uwb-field-results/sandbox/nightly_实际时间戳"
"$PYTHON" tools/field_20261024_25/run_nightly.py \
  --data-root "$DATA_ROOT" --output "$OUTPUT_ROOT" --max-hours 6 --resume
```

恢复不延长初次启动的6小时截止时刻；超过预算后保留未完成项。
源码、配置、输入SHA、Python/依赖版本或作业计划变化时，恢复会拒绝混入旧结果，
应保留旧目录、修复后另起有版本的新输出目录。
通过项仅在日志和预期产物仍存在、哈希仍一致时跳过；文件存在本身不是通过依据。
同一输出目录由进程锁保护，另一端应使用独立目录，不要强行删除锁或共享写入。

退出码：0=有限计划完成；1=有失败/超时；2=有阻塞或配置/参数错误；
3=预算用尽；130=收到中断并保存状态。**非0不等于整套实验无效**，先看每项具体原因。
明早先读summary，再读失败日志、bagQC及provenance；没有独立参考验收前不输出轨迹RMSE。
