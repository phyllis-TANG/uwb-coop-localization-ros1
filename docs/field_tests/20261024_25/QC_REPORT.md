## 文件与bag全量检查

两天tar.gz完整下载38,399,544字节，SHA256为 `b7cec6f75584e583e66946fd669dc7495d10e3bcbebc0b67fa480b65b53fd1bf`；完整gzip/tar读取85个成员、22个bag。归档`.sha256`文本第一字段与实际重算值相符。T08–T15正式bag逐个实际读取并重算SHA，全部与操作员现场记录一致。

八包总消息311,144条，均可根据嵌入schema完整解码，没有多余未消费的消息字节。包含两车raw UWB、ranges、odom、imu、电压和预期运动车辆的cmd_vel；schema、类型、消息数和完整精确路径保存在manifest/审计结果。ROS运行环境并非读取这些uncompressed ROS1 bag的必要条件。

Car1的52,758条原始Frame3 JSON/packet通过头、长度、校验和、节点及距离/RSSI/设备时间字段对应检查，未发现packet与JSON不一致。两车raw/ranges按相同header配对后，节点数和距离零不一致（容差1e-7m）；未配对均位于订阅首尾，未发现内部配对缺口。所有raw及ranges帧非空，所有简化测距条目有限且为正。`quality=NaN`是当前驱动/桥接设计的未知质量，不能当作数值置信度输入。

传感器header/seq未发现重复、倒退或缺号。两车UWB设备system_time相邻帧都增加20ms；local_time增量19–21ms。这支持本次记录时间序列连续，不自动证明无线层无丢包或物理时间已经同步。

活动定义为odom水平速度>0.005m/s或|角速度|>0.02rad/s；区间相对bag第一条接收消息。T12/T13两车活动重叠约23.92/23.67s。路径与角度是反馈记录，不是真实地面长度/转角。T10/T11动作完整，但前静止仅约10/13s，未达到原计划20s；后处理按实际覆盖分析，不凭此单项要求重录。

接收间隔最大约0.642s时，header/device时间仍连续，符合缓冲/接收调度的可能表现，不当作已经证实的无线断流。接收减header偏差有负值、随包/车不同，时钟偏差和接收调度未分离，不使用全局固定延迟。NTP同步状态、文件名北京时间、VM显示PDT都不能直接证明跨设备或视频毫秒同步。

`/rosout`有旧锁存启动日志和日志时间反序，不能按传感器重置处理。`/tf`和`/tf_static`被请求录制但没有实际消息。Car2 `odom.position.z`是已知驱动yaw相关字段，不是真实高度；Odometry frame也不是房间真值，空间关系需离线显式建立。

## 相机及几何验收缺口

- 黑框实际边长144mm，不能用打印标题150mm。棋盘10×7格、9×6内角点，实测192×134mm，两个方向格距分别计算。
- IMG_7337倾斜片29张抽样中27张完整检出54内角点；本轮探索性试算RMS1.854原编码像素。交替分组焦距差约3.1%、主点cy差约47.4px，不能当作最终精密内参。旧片单独RMS5.057px，两片无筛选合并3.922px，不无条件合并。
- 7337带显示rotation=-90°，试算在关闭自动旋转的3840×2160编码坐标系进行。竖幅不得被强拉成横幅；旋转显示图像时需同步变换角点及K。
- 车体方向对齐的“标记中心指向天线”偏移：Car1 `[+0.07,-0.13,-0.20]m`，Car2 `[-0.17,+0.025,-0.03]m`。它们不是原生ArUco坐标外参，也不是base_footprint至天线。Car2略倾斜、角度未测，参考片还出现可能弯曲；不设为已知零倾角。
- 每片内部固定、片间角度可能变，不能用一份房间外参覆盖所有视频。共同静态背景能否恢复原片机位须检验，不能预先承诺厘米级。
- P位置与Q独立检查点实际误差、镜头/对焦/处理一致性及同步都未量化。低重投影误差不等于真实空间精度；Q不能用于拟合后再称独立检查。

## 原件重取与视频检查入口

从仓库根目录运行，设置仓库外的新目录：

```bash
DATA_ROOT="$HOME/uwb_field_data_20261024_25"
OUTPUT_ROOT="$HOME/uwb_field_results_20261024_25"
python3 tools/field_20261024_25/prepare.py --data-root "$DATA_ROOT" \
  --assets bags camera_reference T08_video T09_video T10_video --extract
python3 tools/field_20261024_25/audit_bags.py --data-root "$DATA_ROOT" \
  --output "$OUTPUT_ROOT/bag_qc"
python3 tools/field_20261024_25/audit_videos.py --data-root "$DATA_ROOT" \
  --assets camera_reference T08_video T09_video T10_video \
  --output "$OUTPUT_ROOT/media_qc" --full-decode
```

下载/解压工具用Python3.8+标准库；bag读取另需NumPy，按入口的requirements.txt在隔离环境安装。视频检查另需PATH可见的ffprobe和ffmpeg。已有正确缓存时可在prepare命令加`--offline`；`--output`使用新的输出目录。bag审计先校验所有输入SHA，再解析，输出`bag_qc.json`与`BAG_QC_REPORT.md`；退出码0=通过、1=QC失败、2=输入/解析错误。视频检查输出`video_qc.json`。下载、CRC、全片解码及消息审计会生成自己的证据，不以本报告代替本端运行日志；本报告数值来自已经读取的原文件而非计划目标。
