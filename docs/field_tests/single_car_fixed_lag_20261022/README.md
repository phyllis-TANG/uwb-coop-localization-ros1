# 单车 20 秒固定窗口回放（2026-10-22）

在已合并的 [Python 顺序回放基准](../single_car_sequential_replay_20261022/README.md) 上实现固定窗口。模型仍为固定天线高度的 SE(2) Odom＋UWB；没有新增独立 IMU 因子，也没有调整基站、P1 修正、外参、权重、统计窗或人工终点评价窗。

冻结设置见 [protocol.json](protocol.json)，两包三组结果见 [results/REPORT.md](results/REPORT.md)，研究判断与后续见 [results/INTERPRETATION.md](results/INTERPRETATION.md)，全部统计与复核见 [results/summary.json](results/summary.json)。本轮只使用原来的正常包 005135 和 N10 异常包 004023，两者都是开发数据。

## 三组对照

| 方法 | 因子定义 | 求解初值与导数 | 历史信息 |
|---|---|---|---|
| 原版全历史 | 冻结的历史求解器 | 每次由对齐 Odom 初始化，数值导数 | 完整重线性化 |
| 解析全历史 | 与原版相同，残差等价已经独立验证 | 上次成功图＋Odom 推进，解析导数 | 完整重线性化 |
| 20 秒固定窗口 | 同上，加线性化边界先验 | 同上 | 窗口内重线性化，旧信息压缩保留 |

中间一组用于区分求解器改动与固定窗口的影响。解析求解采用 SciPy `least_squares`、TRF、稠密精确线性求解器、最多 50 次残差评价，三个终止容差都是 `1e-7`。这不是 GTSAM/iSAM2 实现。

## 边缘化与内存边界

每秒一个状态，窗口包含两端点时最多 21 个求解状态。加入新状态后，消元前最多短暂保留 22 个状态。超出窗口的最老状态仅连到下一状态，因此边界先验仍只有三个变量。

消元只使用：已有边界先验、最老状态的 UWB 因子、最老状态到下一状态的 Odom 因子。窗口内其余因子继续显式保留，避免观测被重复计入。先在上次维护的状态处构建残差和解析导数，QR 消去旧状态，再 QR 压缩剩余三维系统，保留先验矩阵及非零仿射残差。先验使用世界系 XY 和包裹到 ±π 的航向差；线性化后不再恢复旧非线性因子。

这保留了该线性化系统中的历史信息，而非与每次完整批量重线性化严格等价。若未来存在大幅重新定位、图拓扑变化或新因子跨越已消元状态，需要重新审视边界和线性化策略。

Odom 缓存保留插值所需的前一个端点及后续消息；测距缓存仅保留可能进入未来统计窗的消息。每个输入流最多 512 个样本，异常时钟/数据缺口导致容量超限时显式报错。已发布历史交给外部日志回调，估计器只维护上次发布状态。离线读取器的诊断列表和外部结果文件仍随 bag 长度增长，不应据此声称整个实验进程内存恒定。

## 因果性、连续性和耗时

- 仍按记录接收顺序逐条输入，不读取未来消息，也不对整包消息头排序或拟合时钟修正。
- 状态 `t` 在接收时钟 `t+1 s` 关闭原有 ±0.4 秒中位数统计窗；等于截止时刻的消息计入，关闭后不被迟到观测重写。
- Odom 插值两端必须已收到。缺少包围区间时明确报告；EOF 不产生超出最后记录时刻的时钟。
- 前两个有效状态仅作预测；未收敛/数值异常不会被接受为融合结果，回退到维护状态的 Odom 预测。边界先验秩异常和缓存容量超限属于显式错误。
- 连续性指标为“本次发布车体 XY 与上次发布车体 XY 经 Odom 推进后的距离”，航向同样记录。首次图初始化与后续常规修正分开统计；它不是连续轨迹真值误差。
- `solve_wall_s` 包括构建优化目标和求解；`marginal_wall_s` 单列旧状态消元；`update_wall_s` 还包括统计窗构建和缓存裁剪。外部日志回调、逐消息输入与 ROS 通信不在完整更新计时内。
- 同一进程中依次运行三组对照，设置 OpenBLAS/OMP 单线程，记录单次实测最坏值和 p95。计算队列由相同的 1 Hz 虚拟工作者模型估计，不是 ROS 队列实测。固定状态数和迭代预算约束数值工作量，不能保证操作系统硬实时截止期。

每组都保存当时输出 `published.csv`、包含求解状态与先验的 `updates.json`，以及整包结束时仍留在估计器内的 `final_active_states.csv`。固定窗口这一文件只有最后窗口，不能当作完整历史平滑轨迹。终点只用于回放结束后的评价，不传入估计器。

## 复现

在仓库根目录、Python 3.12 环境中：

```bash
python -m pip install -r tools/requirements-single-car-replay.txt
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest discover -s tools -p 'test_single_car_*.py' -v
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python tools/run_single_car_fixed_lag.py --output fixed-lag-results
python tools/plot_single_car_fixed_lag.py fixed-lag-results
```

输入 bag 必须位于协议指定的仓库路径且通过 SHA-256 校验。输出目录必须不存在。`--dependency-path` 可指定额外的 rosbags 安装目录，程序在导入 NumPy/SciPy 后追加它。程序不会启动 ROS、串口或小车运动。

运行时 [input_manifest.json](results/input_manifest.json) 记录协议、源代码、数据哈希、实际依赖版本与线程设置；检查运行期间代码和协议未变。原版两个数值源文件及历史求解器保持未改动。

## 验证范围与后续

25 项测试覆盖原版残差等价、初始/相关先验的解析导数、QR 与完整 Schur 消元的 Hessian/梯度/最小化代价一致、非零先验残差、保留观测不被重复计入、纯 Odom 先验协方差传播、非零外参转弯、±π 航向连续性、长期状态与缓存边界、未来消息修改/截断、截止边界、迟到观测、缺少插值端点、失败回退和秩异常。

两个真实包检查三组的状态时刻、Odom 插值、测距中位数和支持样本一致；原版重跑复现已归档位置；固定窗口与解析全历史在首次消元前输出一致；截断到 30 秒后的已发布输出不变，该截断已包含多次真实边缘化。

本轮用于判断固定窗口在现有模型上的计算量和更新连续性。没有连续真值，起点/+Y 朝向仍是外部输入，近似几何中心是否等于 Odom 参考点仍待现场核实。后续应先在未参与开发的录包上保持本协议验证，再做 ROS 按真实时间回放和车载耗时测试。Odom 上游是否使用陀螺仪的排查与独立 IMU 因子仍分开处理。
