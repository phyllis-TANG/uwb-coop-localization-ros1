## 2. 三层差异结论

### 已有方法已经覆盖的部分

- **固定窗口完整性与prior故障不是空白。** P1 [§II-B Eq.(5)、§III p.3184、Eqs.(11)–(19)](https://par.nsf.gov/servlets/purl/10203881)已经把窗口前故障作为prior故障纳入假设；还区分检测统计与完整性风险/可用性。
- **“正常链被坏参照错归责”和多子集检测不是新问题。** P3 [§3.3、Figs.2/3/6、Algorithms1/2](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1190296/full)讨论异常基节点和优化掩蔽；P5 [§4.1–4.2](https://www.mdpi.com/2076-3417/16/10/5137#sec4-applsci-16-05137)正面研究坏移动参照、masking/swamping及LOO/LTO几何归责。
- **拒绝归责也已有。** P5 [§2.1/Table1](https://www.mdpi.com/2076-3417/16/10/5137#sec2dot1-applsci-16-05137)规定5邻居完整子集库、4邻居仅LOO、3邻居只检测/不归责；所以unknown本身不能作为B贡献。
- **跨历元配置一致先验和可信检查点已有明确声明。** P4[公开摘要/贡献3](https://www.sciencedirect.com/science/article/abs/pii/S0273117726013074)已这样表述。全文未获，不能断言其触发/重建细节与我们相同，也不能假装它没做。
- P2[§4、p.1513、§6](https://ira.lib.polyu.edu.hk/bitstream/10397/93579/1/Wen_Integrity_Monitoring_Gnss.pdf)已有滑窗FDE并明确最大残差未必是真故障。P6已有概率处理LoS/NLoS以保留有用协同，P7已有UWB/MHSS。P8已有相关FGO后验、二阶假设及PL有效/业务可用/导航继续的区分。换成UWB、IMU、FGO、月球背景、未知状态或阈值不构成新意。

### 需要复现或取得全文才能判断的部分

1. **P4全文是明确缺口。** 要核查其隔离集更新、可信检查点如何得到、配置变更怎样重建prior、何时拒判/再准入及多故障范围。不能仅凭摘要把A/B判为“已有全做”或“全没做”。
2. P5完整方法是6机器人、5移动邻居、单坏peer位置广播、健康测距、同步投票的snapshot FDI，不评价融合后端和prior恢复。我们是两车＋有限墙锚，故障也可能在距离、墙链或历史；这些是**适用条件差异**，不是自动成立的贡献。先在原假设下复现，再声明任何适配。
3. P5当前代码与论文参数/回退/投票不一致；两种候选基线的完整步骤、许可和复现关卡见[BASELINES.md](BASELINES.md)。不得用缺失投票、未计prior故障或任意简化阈值的版本代表原方法。
4. P8[§V-D5](https://arxiv.org/abs/2610.32259v1)明确当前因子移除不等于消掉持续历史故障；它保留相关posterior但并未提供任意历史污染修复保证。利用其局限提出问题可以，不能据此宣称我们已解决。

### 尚未成立的贡献候选

以下属于本次推断和待检验设计，**没有实现、理论证明或新实验结果**：在有限冗余下，先检查“当前观测是否足以在若干污染解释间作决定”，再决定peer采用/限影响/暂缓，并使这一决定与历史prior处理和再准入一致。必须有额外的可检验条件或机制，不能把现成子集一致性加状态机重新命名。

一个基本边界是：单个peer距离冲突可由测距偏置、任一车辆沿视线的位置偏差或两者组合解释。墙/运动信息也不可信时，矩阵满秩不等于故障来源可辨；不可识别条件下不能同时承诺正确归责和零代价协同。

## 3. 候选题A：有条件优先

**一句话问题**：用于判断车间测距的参照也可能受污染、墙锚冗余有限时，固定窗口双车系统凭什么采用、限制或暂缓peer测距，才能减少另一辆健康车的错误传播并保留正常协同收益？

**拟贡献（待证）**：明确不同污染解释何时可区分的采用条件；在可辨条件下采用peer，在证据冲突/不足时限制传播，并让当前准入、窗口旧因子、边缘化prior和恢复确认语义一致。新意须落在条件、可证/可测的累计影响边界或明确决策改进；不是“多影子＋阈值＋恢复”。若P4已提供同一机制，应重新定位。

**最小必要证据**：

- 同轨迹/噪声/初值/到达流下，分开注入peer距离错、墙参照错、peer状态错、历史污染与共同原因；保留不可辨和正常协同有益的反例。检测器只用已到达观测，不用真值或故障标签。
- 与两种完整文献基线及已有D0/D1公平比较；分别报健康车与故障来源车的误差尾部、伤害事件、正常协同收益、拒判车秒、连续可用率、恢复延迟/删失和计算/通信代价。
- 单独消融参照可信性条件与历史处理；当前倍率恢复1、旧因子退出窗、prior影响消退和独立参考下误差恢复分别计时，不混作同一个“恢复”。
- 实包若要支持精度，需要先通过独立时空参考验收；否则只报告实现/动作与停点开发诊断。整包开发/留出不改，不能因参考不足使用融合轨迹充真值。

**审稿人最可能质疑**：是不是P3/P5的子集共识、P1/P4的SS及prior处理换了载体？健康参照如何被证明健康？共同平移/共同偏差时凭什么辨别？收益是否仅来自少用peer或更松的可用性口径？

**收缩条件**：若完整原方法已达到同样收益，或候选只能靠长期拒判避免伤害，A停止主张方法新意。若历史重建与实包参考无法按时验收，先只研究局部peer准入条件，不宣称整体完整性或在线修复；仍无可辨差异时转B或只保留为平台诊断。

## 4. 候选题B：范围更小的备选

**一句话问题**：单车低冗余UWB固定窗口中，当排除目标后的参照仍可能被其他链及prior污染，怎样减少健康链错归责，并量化拒判与恢复所损失的定位可用性？

**拟贡献（待证）**：把“证据足够才作单链归责”的条件和历史一致再准入落到一个可复现机制；比较相同健康链误抑制预算下的漏检、拒判/可用性及恢复，而非仅让影子分数变小。unknown名称、多个排除图、增大阈值、减少触发次数本身均不足。

**最小必要证据**：保留现有跨链污染的全部正反例；新增未暴露seed/条件而不对原触发点调参；区分健康链错误抑制、真实故障漏检、未知链秒与无测量；加入共同原因、先验残留和正常有益约束，提供配对代价曲线及历史处理消融。实包没有故障标签时只报动作，不把动作叫误报。

**审稿人最可能质疑**：P2已指出最大残差错归责，P5已有低冗余拒判，P4已声明跨历元先验/恢复。方案是否只是更保守而代价被隐藏？独立影子共享其他故障时为何可信？

**收缩条件**：若降低健康链误动作仅靠增加unknown、漏检或恢复等待，且没有有用的折中或新条件，则不作为独立方法贡献。可收缩为已有FGO监测器的失效条件/评测协议研究，但能否形成会议论文仍需导师判断；更小不等于更容易发表。
