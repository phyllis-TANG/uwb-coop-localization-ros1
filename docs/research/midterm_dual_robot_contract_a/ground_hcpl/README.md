## 调查先验与原始输入

运行输入采用 #145 提交 `d3b39fa9003519f70aef4abfdd050fc969a4a513` 的 `docs/research/ground_b_round1/runtime`。其中 `geometry.json` 明确给出调查位置和航向的有效时刻 `prior_state_s=1`。两个车体里程坐标系从 t=0 开始累积，调查的天线位置和航向则对应 t=1。滤波在 t=1 直接对调查先验作九条测距更新；首个运动过程因子连接 t=1 和 t=2，其前不添加过程噪声。

运行时接收顺序、每条记录的采样时标、源 ID 与载荷均取自 `events.jsonl.gz`。每个整秒各取两车的同戳里程和 UWB 帧，须在各自 t+1 s 截止前收齐。选用 Car1 的正向 peer 行和每车四条墙锚斜距。每个包保存四个源 ID、各自接收时刻、锚顺序及输入到齐时刻。归档保留每步加杆臂后的天线位移、先验、创新、增益、后验与对应协方差。[公式和适用条件](FORMULAS.md)

仅在估计与判定结束后，从 #143 提交 `01e588021e7e3ddd918b1d1fc9561973373758c6` 的种子 101 正常归档读取索引 200 的真值及第十秒基线。#143 同历元单独拟合一个自由 peer 偏差得到 0.138768 m，本例递推九个随机游走偏差后的 peer 估计为 0.014743 m。#142 的候选区域 PL 采用另一种估计方法。

## 可辨识性与结果边界

单历元的九条观测对 13 个未知数不能给出唯一解；第一包附有一组残差为零的状态方向。十历元共有 130 列，仅计测距与里程时秩为 126。引入相邻偏差的随机游走因子和调查先验后得到满列秩。本例给出条件模型下的数值保护级和告警。剩余偏差的物理上界、线性化影响、场景覆盖和实际交付时间仍是证明运行完整性所需的独立证据。

## 复现

在仓库根目录使用 Python 3 和 NumPy。默认按上列固定提交读取源文件；本地缺少相应 Git 对象时先取两个 PR 头。仅运行估计可使用 `--runtime-only`，这条路径只需 #145 的两份输入文件。若已下载归档，可用 `--runtime-dir DIR` 指定这两份输入的目录，用 `--evaluation-dir DIR` 指定 #143 正常种子 101 的 `truth.json.gz` 和 `records.json.gz` 所在目录。测试读取同一固定输入，允许通过 `HCPL_RUNTIME_DIR` 指定本地副本。

```sh
git fetch origin refs/pull/143/head refs/pull/145/head
export OPENBLAS_NUM_THREADS=1
t=tools/midterm_dual_robot_contract_a/ground_hcpl
python3 "$t/example.py" > /tmp/epoch10.json
python3 "$t/recompute.py" /tmp/epoch10.json /tmp/independent.json
python3 "$t/test_reference.py" -v
```

独立核算从归档观测包和调查先验重建每个前缀的白化方程并作 SVD。由上一个前缀的独立 SVD 解预测本期线性化点，归档的滤波中间量只用于核对。十个前缀全状态最大绝对差约 1.23×10⁻¹³，双车三种 HCPL 最大绝对差低于 9×10⁻¹⁵ m。针对性测试覆盖首帧无运动与无过程噪声、纯转向杆臂、局部里程坐标变换、时间平移、因果前缀、迟到及缺包处理。[逐步数据](epoch10.json) · [独立复算结果](independent.json)
